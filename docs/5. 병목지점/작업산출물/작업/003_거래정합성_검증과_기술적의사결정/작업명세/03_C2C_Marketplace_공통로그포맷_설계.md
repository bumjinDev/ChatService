# C2C Marketplace 공통 로그 포맷 설계

- 작성일: 2026-11-10
- 작업기록: [작업기록](../작업기록.md)
- 상태: 설계안. 코드·설정에는 아직 적용하지 않음.

## 1. 공통 로그 포맷

모든 테스트에서 동일하게 사용하는 형식이다.

```text
시각 - 테스트명 - 기능명 - 파일명 - 메소드명
| 실행ID=... 요청ID=... 단계=...
| 테스트별 확인 항목...
```

위 형식은 읽기 쉽게 줄을 나눈 예시이며, 하나의 로그 사건을 나타낸다.

| 항목 | 의미 |
|---|---|
| 시각 | 로그 발생 시각 |
| 테스트명 | 어떤 테스트인지 구분 |
| 기능명 | 처리 중인 기능 |
| 파일명·메소드명 | 로그가 발생한 코드 위치 |
| 실행 ID | 반복 실행을 구분 |
| 요청 ID | 하나의 요청을 시작부터 종료까지 추적 |
| 단계 | 시작·수량 판단·저장·커밋·롤백·응답 등 |

### 기록 원칙

- **저장 로그와 커밋 완료 로그는 구분한다.** 저장 로그만으로 거래 성립을 확정하지 않는다.
- 수량은 **실제 판단에 사용한 값**을 기록한다. 로그를 위해 다시 조회한 값으로 대체하지 않는다.
- 요청 시작 시 아직 조회하지 않은 정보는 해당 데이터를 조회한 뒤 기록한다.
- 수량 부족을 확인하면 해당 시도를 종료한다. 결과 미확인 시 저장된 기존 처리 결과부터 확인한다.
- 요청 전송 순서와 거래 성립 순서를 구분한다. 함께 전송했다는 사실만으로 서버 처리의 겹침을 단정하지 않는다.
