# 003 거래정합성_검증과_기술적의사결정

- 생성일: 2026-11-09
- 작업 목록: [00_작업목록](../../00_작업목록.md)

## 1. 작업 개요

### 1.1 목적과 범위

거래 상황에 맞는 요청을 구성하고 실행 결과를 관찰해 정합성이 지켜지는지 확인한다. 관찰 결과를 바탕으로 비즈니스 규칙을 확정하거나 보완하고, 문제를 해결하기 위한 기술적 의사결정과 수정 후 검증으로 이어 간다.

정합성이 틀어졌는지는 수량 초과 금지와 유효 예약 보호처럼 실행 전에 정한 기준으로 판단한다. 실행 뒤에는 정한 규칙을 위반한 결과, 규칙은 지켰지만 불편한 구매 경험, 아직 정책이 없어 판단하기 어려운 결과를 구분한다.

테스트는 기존 예약·주문이 없는 상태의 세 가지 기본 경합(예약–예약, 예약–등록 가격 구매, 등록 가격 구매–등록 가격 구매)에서 시작해, 기존 거래가 있는 상황과 예약의 주문 전환, 취소 후속 시나리오, 취소가 여러 지점에서 복합적으로 발생하는 상황으로 넓힌다. 목적, 시나리오 구성 방향, 진행 순서는 [작업명세 01 C2C_Marketplace_거래정합성_테스트_진행계획](작업명세/01_C2C_Marketplace_거래정합성_테스트_진행계획.md)에 있다.

### 1.2 관련 작업

- [002 합의가격주문_취소와_발송등록_경합](../002_합의가격주문_취소와_발송등록_경합/작업기록.md): 이 작업의 기본 비즈니스 시나리오는 작업 002의 인물, 수량, 요청 순서를 이어받지 않고 새로 구성했다. 작업 002에서 관찰한 사실은 필요할 때 참고한다([기타문서 01 C2C_Marketplace_기본비즈니스시나리오_구성과_논의근거_종합정리_2026-11-09](기타문서/01_C2C_Marketplace_기본비즈니스시나리오_구성과_논의근거_종합정리_2026-11-09.md)의 「2.4 기존 작업의 활용 범위」).

## 2. 작업 계획

1. 기존 예약·주문이 없는 상태의 세 가지 기본 경합을 각각 세부 작업 하나로 테스트한다. 각 세부 작업은 기능을 한두 개씩 묶어 테스트한다([작업명세 02 기능_중심_테스트_설계_및_진행_방향](작업명세/02_기능_중심_테스트_설계_및_진행_방향.md)).
2. 기존 예약이나 주문이 있는 상태와, 기존 예약을 결제해 주문으로 전환하는 도중의 상태로 넓혀 테스트한다.
3. 구매 철회와 재구매 목적 취소를 구분하도록 취소 기능을 수정한 뒤, 취소 후속 시나리오를 테스트한다.
4. 취소가 여러 거래 지점에서 복합적으로 발생하는 상황을 테스트한다.
5. 실행 결과에서 정한 규칙의 위반이 확인되면 처리 과정과 원인을 조사하고 기술적 해결책을 검토한다. 수정한 내용은 필요한 범위에서 다시 검증한다.

각 단계의 상세 내용은 작업명세 01에 있다.
