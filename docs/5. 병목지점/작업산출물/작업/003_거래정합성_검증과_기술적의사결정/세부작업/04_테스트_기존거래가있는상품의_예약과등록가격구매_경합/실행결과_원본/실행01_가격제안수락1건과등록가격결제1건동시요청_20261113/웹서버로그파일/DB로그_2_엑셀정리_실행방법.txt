DB로그_2_엑셀정리.py 실행 방법

[하는 일]
DB로그_1_p6spy기록_CSV추출.py가 만든 p6spy 기록 CSV와 웹애플리케이션로그_1_CSV추출.py가 만든 웹 애플리케이션 로그 CSV를 읽어, 기존 주문과 기존 예약이 있는 상품에 함께 보낸 수락·결제 검증 요청 2건이 DB에 보낸 SQL과 커밋·롤백을 확인할 수 있게 엑셀 파일 하나로 정리한다.
2건은 판매자가 새 흥정 구매자의 가격 제안을 수락하는 요청 1건(accept-new)과 새 등록 가격 구매자가 등록 가격으로 결제하는 요청 1건(buy-new)이다.
요청과 p6spy 기록은 로깅 설계 문서(작업명세 04·05) 「1.1 애플리케이션 로그와 p6spy 기록」에 적힌 방법으로 잇는다. 같은 서버 스레드에서 그 요청의 요청수신 로그부터 요청응답 로그 사이에 남은 p6spy 기록이 그 요청의 것이다.
대상은 실행 ID가 --run-id와 같은 요청 가운데, 검증 요청 결과 파일(검증요청_결과.csv)에 서버 로그 요청 ID가 적힌 검증 요청이다. 요청은 새 흥정 구매자의 수락 요청, 그다음 새 등록 가격 구매자의 결제 요청 순서로 둔다.
같은 실행 ID로 서버 로그에 남은 준비 요청 2건(기존 주문을 만든 준비 결제 prep-order-existing, 기존 예약을 만든 준비 수락 prep-accept-existing)은 엑셀에 넣지 않는다.
구간은 웹 애플리케이션 로그 엑셀의 시트 3과 같다(요청의 로깅 설계 문서 로그 하나와, 같은 요청에서 그 바로 앞에 남은 로그 사이).
p6spy 기록이 어느 구간에 드는지는 서버 로그 파일의 줄 순서로 정한다. p6spy 기록의 시각은 1/1,000초까지라 1/1,000,000초까지 있는 설계 로그 시각과 비교하면 같은 1/1,000초 안의 앞뒤를 가를 수 없기 때문이다.
입력 파일은 읽기만 한다. 출력 파일이 이미 있으면 덮어쓰지 않고 중단한다.

[시트 구성]
1_요청별SQL          요청마다, 구간마다 그 요청 자신의 p6spy 기록을 표 하나에 둔다.
                     표의 열은 원본 줄 번호, 시각, SQL 실행에 걸린 시간, 구분, 연결 번호, 직전에 실행되는 SQL, 바인드 값을 넣은 SQL이다.
                     「직전에 실행되는 SQL」 칸에는 로깅 설계 문서 「2.1 요청 하나에서 로그가 남는 순서」의 SQL 이름을 적는다.
                     수락 요청은 작업명세 04의 「직전에 실행되는 SQL」 열의 이름(가격 제안 조회, 상품 조회, 대화 조회, 같은 구매자의 예약 조회, 상품의 예약 조회, 예약 INSERT,
                     대화 상태 이벤트를 만들기 위한 조회, 가격 제안 UPDATE)이다.
                     결제 요청은 작업명세 05의 「앞 로그부터 이 로그까지 p6spy에 남는 SQL」 열의 이름(상품 조회, 상품의 예약 조회, 주문 INSERT 등)이다.
2_요청별시간         요청 2건을 한 표에 한 행씩 둔다.
                     트랜잭션 경과 시간, DB 연결 대기(추정), 대화 상태 이벤트를 만들려고 대화마다 반복하는 예약 조회의 건수와 시간을 계산해 둔다.
                     트랜잭션 경과 시간의 끝은 커밋완료 구간의 commit 기록이다. 결제 요청의 요청응답 구간에 남은 응답 조회 트랜잭션의 commit 기록은 쓰지 않는다.
                     반복하는 예약 조회는 커밋전 구간에 남은 예약 조회 가운데 상품 ID와 예약 상태로 조회한 기록이다.
3_구간별다른요청SQL  기준 요청마다, 구간마다 그 사이에 남은 다른 요청(수락 요청과 결제 요청 모두)의 p6spy 기록을 서버 로그 파일의 줄 순서대로 표 하나에 둔다.
                     원본 줄 번호를 누르면 시트 1의 그 기록으로 이동한다. 건수를 세거나 영향을 판단하는 열은 두지 않는다.
각 시트 아래에는 열마다 무슨 데이터인지 적은 열 설명 표가 있다. 시트 1과 시트 3은 요청마다 엑셀의 행 그룹으로 묶었다.

[실행 명령] PowerShell에서 아래 두 명령을 차례로 실행한다. 웹애플리케이션로그_1_CSV추출.py와 DB로그_1_p6spy기록_CSV추출.py를 먼저 실행해 CSV 두 개를 만들어 둔다.
엑셀 파일을 다시 만들 때는 엑셀에서 그 파일을 닫고 기존 파일을 지운 뒤 실행한다.

[인자]
--p6spy             DB로그_1_p6spy기록_CSV추출.py가 만든 p6spy 기록 CSV. 이 실행의 서버 로그에는 바인드 값을 넣은 SQL이 25만 자를 넘는 기록이 있어, 스크립트가 CSV 칸 길이 한도를 늘려 읽는다
--web-csv           웹애플리케이션로그_1_CSV추출.py가 만든 웹 애플리케이션 로그 CSV. 요청의 서버 스레드, 로깅 설계 문서 로그의 줄 번호와 시각, 인증 성공 시각을 읽는다
--run-id            정리할 수락·결제 경합의 실행 ID. 15:02 「실행 시작」 그룹이 만든 실행 ID다
--prepare-baseline  「요청 전 확인」 그룹이 실행 폴더에 남긴 요청 전 기준값 파일(요청전_기준값.json). 역할별 회원 ID, 대화 ID, 새 흥정 구매자의 제안 ID를 찾는다
--request-result    「결과 집계」 그룹이 실행 폴더에 남긴 검증 요청 결과 파일(검증요청_결과.csv). 검증 요청마다 요청 종류와 서버 로그 요청 ID를 읽는다. 이 파일에 서버 로그 요청 ID가 있는 요청만 엑셀에 넣는다
--output            만들 엑셀 파일. 폴더가 없으면 만든다

[py -V:3.13]
이 노트북에 설치된 Python 3.13으로 실행하라는 뜻이다. 엑셀 파일을 만드는 openpyxl이 이 Python에 설치되어 있다.

[결과 확인]
실행하면 화면에 요청 건수, 같은 실행 ID로 남았지만 엑셀에 넣지 않은 준비 요청, 요청마다 구매자·서버 스레드·p6spy 기록 건수·구간별 기록 건수·반복하는 예약 조회 건수, 요청 2건의 p6spy 기록 합계, 시트 3에 넣은 행 수, 저장한 파일 경로가 나온다.
직전에 실행되는 SQL 이름을 정하지 못한 기록이 있으면 그 건수도 나온다.
실행01로 실행하면 요청 2건(가격 제안 수락 요청 1건, 등록 가격 결제 요청 1건)이 나온다. 엑셀에 넣지 않은 준비 요청은 prep-accept-existing과 prep-order-existing이다.
수락 요청(accept-new)은 p6spy 기록 13건이 구간별로 수락시작 1, 수량판단 4, 예약저장처리완료 1, 커밋전 5, 커밋완료 2, 요청응답 0으로 나뉜다. 커밋 기록은 15:13:18.212(연결 번호 45902)다.
결제 요청(buy-new)은 p6spy 기록 23건이 구간별로 결제시작 0, 남은수량판단 1, 구매가능수량판단 1, 잔액판단 2, 주문저장처리완료 1, 차감처리완료 1, 커밋전 7, 커밋완료 3, 요청응답 7로 나뉜다.
결제 요청의 커밋 기록은 15:13:18.209(연결 번호 45901)이고, 요청응답 구간의 응답 조회 7건(commit 1건 포함)은 연결 번호 45903이다.
반복하는 예약 조회는 요청마다 4건(대화 4건)이다. 요청 2건의 p6spy 기록 합계는 36건, 시트 3에 넣은 다른 요청의 p6spy 기록은 31행이다.
직전에 실행되는 SQL 이름을 정하지 못한 기록은 없다.
