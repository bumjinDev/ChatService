DB로그_1_p6spy기록_CSV추출.py 실행 방법

[하는 일]
서버 로그(chatservice.log)에서 p6spy 기록(서버가 DB에 보낸 SQL과 커밋·롤백의 기록)만 골라 CSV 파일로 옮긴다.
서버 로그에서 로그 한 건은 날짜와 시각으로 시작하는 줄에서 시작한다. 날짜·시각 줄을 만나면 새 로그로 보고 다음 날짜·시각 줄 전까지의 줄을 그 로그에 붙인 뒤,
로그를 남긴 클래스가 p6spy인 로그만 남긴다.
p6spy 기록 한 건은 SQL 실행 기록이면 머리 줄, 값 자리가 ?인 SQL, 바인드 값을 넣은 SQL의 세 줄이고, 커밋·롤백 기록이면 머리 줄, 빈 줄, 「;」 줄이다.
CSV에는 p6spy 기록 한 건을 한 행으로 둔다. 열은 원본 줄 번호, 스레드 이름, 시각, SQL 실행에 걸린 시간, 구분, 연결 번호, 바인드 값을 넣은 SQL이다.
원본 로그는 바꾸지 않는다. 출력 파일이 이미 있으면 덮어쓰지 않고 중단한다.

[실행 명령] PowerShell에서 아래 두 명령을 차례로 실행한다.

cd "E:\devSpace\SpringBootProjects\ChatService\docs\5. 병목지점\작업산출물\작업\003_거래정합성_검증과_기술적의사결정\세부작업\04_테스트_기존거래가있는상품의_예약과등록가격구매_경합\실행결과_원본\실행05_기술적의사결정_상품별잠금synchronized_수락1건과등록가격결제17건_20261126\웹서버로그파일"

py -V:3.13 .\DB로그_1_p6spy기록_CSV추출.py --log .\chatservice.log --output "E:\devSpace\SpringBootProjects\ChatService\docs\5. 병목지점\작업산출물\작업\003_거래정합성_검증과_기술적의사결정\세부작업\04_테스트_기존거래가있는상품의_예약과등록가격구매_경합\실행결과_가공\실행05_기술적의사결정_상품별잠금synchronized_수락1건과등록가격결제17건_20261126\실행05_DB로그_1_p6spy기록_원본추출.csv"

[인자]
--log     원본 서버 로그 파일
--output  만들 CSV 파일. 폴더가 없으면 만든다

[py -V:3.13]
이 노트북에 설치된 Python 3.13으로 실행하라는 뜻이다. python 명령은 Python 설치 관리자로 연결되어 있어 쓰지 않는다.

[CSV의 열]
원본 줄 번호          서버 로그에서 이 p6spy 기록이 시작되는 줄의 번호
스레드 이름           이 기록을 남긴 서버 스레드
시각                  서버가 로그 줄 맨 앞에 기록한 시각(한국 시각, 1/1,000초까지). 서버 로그의 글자 그대로다
SQL 실행에 걸린 시간  p6spy 기록의 「took」 값. 단위는 밀리초(ms)다
구분                  p6spy 기록의 구분. 서버 로그의 글자 그대로다. statement는 SQL 실행, commit은 커밋, rollback은 롤백이다
연결 번호             p6spy 기록의 「connection」 값
바인드 값을 넣은 SQL  값 자리에 실제 값을 넣은 SQL. 커밋·롤백 기록에는 SQL 문장이 없어 「-」로 둔다

[결과 확인]
실행하면 화면에 원본 줄 수, 로그 건수와 그 가운데 p6spy 기록 건수, 구분별 p6spy 기록 건수, 첫 기록과 마지막 기록의 시각, CSV에 넣은 기록 건수, 저장한 파일 경로가 나온다.
SQL 줄이 두 줄이 아닌 SQL 실행 기록이나 머리 줄을 읽지 못한 기록이 있으면 그 건수와 원본 줄 번호도 나온다.
실행05의 서버 로그로 실행하면 원본 26348줄에서 로그 14586건이 나오고, 그 가운데 p6spy 기록 5881건(statement 4303건, commit 1568건, rollback 10건)이 CSV에 들어간다.
rollback 10건은 구매 가능 수량 부족으로 거절된 검증 요청 10건(등록 가격 결제 요청 pay-08부터 pay-17까지)의 롤백 기록이다. SQL 줄이 두 줄이 아닌 기록과 머리 줄을 읽지 못한 기록은 없다.
SQL 끝에 for update가 붙은 기록은 없다. 실행05의 서버는 상품 행의 잠금을 얻는 조회를 실행하지 않는다.
첫 기록 시각은 20:20:51.193, 마지막 기록 시각은 21:23:23.213이다. 검증 요청까지 보낸 실행의 그룹이 요청을 보낸 시간은 21:13부터 21:23까지이고, 검증 요청 18건은 21:20:38부터 21:23:08 사이에 서버에 들어왔다.
20:49:53과 20:50:19에는 같은 실행 ID로 검증 요청을 보내지 못하고 끝난 앞선 실행의 준비 요청 기록이 남아 있다. 이 서버 로그는 20:20:51부터 남아 있어 20:00의 회원 가입 요청은 들어 있지 않다.
