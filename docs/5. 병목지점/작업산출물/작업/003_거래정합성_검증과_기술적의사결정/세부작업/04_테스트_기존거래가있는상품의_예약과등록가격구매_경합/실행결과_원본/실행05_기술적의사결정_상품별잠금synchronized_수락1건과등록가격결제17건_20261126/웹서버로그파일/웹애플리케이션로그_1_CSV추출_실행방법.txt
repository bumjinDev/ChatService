웹애플리케이션로그_1_CSV추출.py 실행 방법

[하는 일]
서버 로그(chatservice.log)에서 웹 애플리케이션 로그만 골라 CSV 파일로 옮긴다. SQL 기록(p6spy가 남긴 기록)은 넣지 않는다.
서버 로그에서 로그 한 건은 날짜와 시각으로 시작하는 줄에서 시작한다. SQL 기록은 SQL 문장 안의 줄바꿈 때문에 여러 줄로 이어지므로,
날짜·시각 줄을 만나면 새 로그로 보고 다음 날짜·시각 줄 전까지의 줄을 그 로그에 붙인 뒤, 로그를 남긴 클래스가 p6spy인 로그를 뺀다.
CSV에는 로그 한 건을 한 행으로 두고, 서버 시각·로그 레벨·서버 스레드·로그를 남긴 클래스·메시지를 열로 나눈다. 메시지는 글자를 바꾸지 않는다.
원본 로그는 바꾸지 않는다. 출력 파일이 이미 있으면 덮어쓰지 않고 중단한다.

[실행 명령] PowerShell에서 아래 두 명령을 차례로 실행한다.

cd "E:\devSpace\SpringBootProjects\ChatService\docs\5. 병목지점\작업산출물\작업\003_거래정합성_검증과_기술적의사결정\세부작업\04_테스트_기존거래가있는상품의_예약과등록가격구매_경합\실행결과_원본\실행05_기술적의사결정_상품별잠금synchronized_수락1건과등록가격결제17건_20261126\웹서버로그파일"

py -V:3.13 .\웹애플리케이션로그_1_CSV추출.py --log .\chatservice.log --output "E:\devSpace\SpringBootProjects\ChatService\docs\5. 병목지점\작업산출물\작업\003_거래정합성_검증과_기술적의사결정\세부작업\04_테스트_기존거래가있는상품의_예약과등록가격구매_경합\실행결과_가공\실행05_기술적의사결정_상품별잠금synchronized_수락1건과등록가격결제17건_20261126\실행05_웹애플리케이션로그_1_원본추출.csv"

[인자]
--log     원본 서버 로그 파일
--output  만들 CSV 파일. 폴더가 없으면 만든다

[py -V:3.13]
이 노트북에 설치된 Python 3.13으로 실행하라는 뜻이다. python 명령은 Python 설치 관리자로 연결되어 있어 쓰지 않는다.

[CSV의 열]
원본 줄 번호        서버 로그에서 이 로그가 시작되는 줄의 번호
원본 줄 수          이 로그가 서버 로그에서 차지한 줄 수. 메시지가 여러 줄이면 2 이상이다
서버 시각           서버가 로그 줄 맨 앞에 기록한 시각(한국 시각, 밀리초까지). 서버 로그의 글자 그대로다
로그 레벨           INFO, WARN, ERROR 등
프로세스 번호       서버 애플리케이션의 프로세스 번호
애플리케이션        로그를 남긴 애플리케이션 이름
서버 스레드         이 로그를 남긴 서버 스레드
로그를 남긴 클래스  이 로그를 남긴 코드의 클래스 이름. 패키지 이름은 서버 로그에서 앞 글자로 줄여 기록된다
메시지              로그 메시지 원문. 여러 줄이면 줄바꿈을 그대로 둔다

[결과 확인]
실행하면 화면에 원본 줄 수, 로그 건수와 뺀 SQL 기록 건수, CSV에 넣은 웹 애플리케이션 로그 건수, 첫 로그와 마지막 로그의 시각, 저장한 파일 경로가 나온다.
실행05의 서버 로그로 실행하면 원본 26348줄에서 로그 14586건이 나오고, SQL 기록 5881건을 뺀 웹 애플리케이션 로그 8705건이 CSV에 들어간다.
그 가운데 이번 테스트에서 추가한 로그(「| 실행ID=」가 들어 있는 로그)는 237건이다.
- 실행 ID가 mpay05-20261126-200038인 로그 237건: 검증 요청 18건(accept-new, pay-01부터 pay-17까지)의 로그 191건과, 준비 요청(기존 주문을 만든 준비 결제 prep-order-existing, 기존 예약을 만든 준비 수락 prep-accept-existing)의 로그 46건
- 검증 요청 18건의 로그 191건은 성공한 결제 요청 7건의 로그 91건(요청마다 13건), 거절된 결제 요청 10건의 로그 90건(요청마다 9건), 성공한 수락 요청 1건의 로그 10건이다
- 요청마다 잠금요구, 잠금획득, 잠금해제 로그가 한 건씩 들어 있다. 서버에 애플리케이션의 상품별 잠금(synchronized)을 반영하면서 더한 로그다
- 준비 요청의 로그 46건은 준비 결제의 로그 26건(13건씩 두 번)과 준비 수락의 로그 20건(10건씩 두 번)이다. 같은 실행 ID로 준비 단계를 두 번 실행했기 때문이다.
  20:49:53과 20:50:19의 로그는 검증 요청을 보내지 못하고 끝난 앞선 실행의 준비 요청이고(상품 ID 262514), 21:14:07과 21:14:14의 로그는 검증 요청까지 보낸 실행의 준비 요청이다(상품 ID 262515)
- 실행 ID가 다른 로그는 없다
첫 로그 시각은 20:20:51.193, 마지막 로그 시각은 21:23:23.207이다. 검증 요청까지 보낸 실행의 그룹이 요청을 보낸 시간은 21:13부터 21:23까지이고, 검증 요청 18건은 21:20:38부터 21:23:08 사이에 서버에 들어왔다.
이 서버 로그는 20:20:51부터 남아 있어 20:00의 회원 가입 요청은 들어 있지 않다.
