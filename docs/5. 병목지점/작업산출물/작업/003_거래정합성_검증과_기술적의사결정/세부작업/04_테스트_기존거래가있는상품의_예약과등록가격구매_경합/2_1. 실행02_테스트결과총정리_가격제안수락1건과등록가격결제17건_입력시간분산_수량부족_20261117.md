## 5. 확인한 사실

**결과 확인 기준을 어긴 것 두 가지**

- **수량 초과:** 주문 20개와 유효 예약 6개를 더한 26개가 상품 등록 수량 16개를 넘었습니다. 주문만으로도 16개를 넘습니다.
- **남은 수량이 주문 수량만큼 줄지 않음:** 새 주문 17개가 생기는 동안 저장된 남은 수량은 13개에서 8개로 5개만 줄었습니다. 등록 수량에서 주문 수량을 빼면 −4개입니다.

**결과 확인 기준을 지킨 것**

- 기존 주문, 기존 예약, 기존 예약 구매자의 가격 제안은 요청 전 기준값과 모든 열이 같았습니다. 기존 예약은 종료 후 DB 조회 시각에 유효했습니다.
- 성공한 요청은 응답과 저장 결과가 같았습니다. 수락은 2개 전부를 예약했고, 결제는 구매자마다 주문 1건과 차감 1건이 생겼습니다.
- 예상하지 않은 주문이나 예약, 한 구매자에게 주문이 2건 이상 생긴 일은 없습니다.
- 조회자별 구매 가능 수량은 계산 방법대로 나왔습니다. 계산에 들어간 남은 수량이 실제 주문 수량과 맞지 않았습니다.

**조회 화면에 나타난 영향**

주문이 등록 수량보다 4개 많은데도 상품은 판매 중이고, 세 조회자 모두 구매 가능 수량이 0 이상으로 나옵니다. 조회 화면만으로는 초과를 알 수 없습니다.

## 6. 계산으로 얻은 것

확인한 값은 출발 전 남은 수량 13개와 종료 후 8개입니다. 「결제 한 건은 자신이 읽은 남은 수량에서 1개를 뺀 값을 저장한다」(로컬 소스에서 확인)와 「출발 시점끼리는 겹치지 않는다」(확인한 사실)에 따르면, 출발 시점 다섯 번에 5개가 줄었으므로 출발 시점마다 1개씩만 줄었다는 계산이 나옵니다.

| 출발 시점 | 그 시점의 새 주문 | 주문 수량만큼 줄었을 때의 남은 수량 | 계산한 저장 남은 수량 |
|---|---:|---:|---:|
| 출발 전 | | 13개 | 13개(확인) |
| 30초 | 2개 | 11개 | 12개 |
| 60초 | 4개 | 7개 | 11개 |
| 90초 | 6개 | 1개 | 10개 |
| 120초 | 3개 | −2개 | 9개 |
| 180초 | 2개 | −4개 | 8개(확인) |

이 계산대로라면 120초의 결제는 「저장된 남은 수량 10개 − 유효 예약 6개 = 4개」로, 180초의 결제는 「9개 − 6개 = 3개」로 판단해 통과했을 것입니다(추론).
