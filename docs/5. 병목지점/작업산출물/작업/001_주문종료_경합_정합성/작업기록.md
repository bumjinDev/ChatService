# 001 주문종료_경합_정합성

## 1. 작업 개요

### 1.1 목적과 범위

결제가 끝난 주문 하나를 구매자, 판매자, 자동 처리가 거의 동시에 끝내려 할 때, 한 주문은 취소 완료, 정상 완료, 환불 완료 가운데 하나로만 끝나야 한다는 규칙(요구사항 BR-005)이 지켜지는지 실제 요청과 Oracle 데이터로 확인한다. 코드를 읽어 추정한 문제를 실행으로 확인하는 작업이므로, 추정한 결과는 가설로 다루고 실행 결과가 가설과 다르면 그대로 기록한다.

범위와 실행 환경은 다음과 같다.

- 대상: 같은 주문을 끝내려는 두 처리가 겹치는 다섯 상황 S1-1~S1-5. 각 상황의 두 요청은 [작업명세 01](작업명세/01_테스트계획_공통.md)의 3절에 있다.
- 실행 환경: 미니PC에 배포된 서버(`http://wherehouse.it.kr:8186/ChatService/`)와 미니PC Oracle의 테스트 전용 계정 `TOYCHAT_TEST`. H2로 실행한 결과는 쓰지 않는다.

## 2. 작업 계획

작업은 다음 다섯 과정으로 진행한다.

| 과정 | 하는 일 |
|---|---|
| 문제 확인 과정 | 코드를 읽고 세운 가설이 실제로 일어나는지 확인한다. 테스트 계획은 [작업명세 01](작업명세/01_테스트계획_공통.md)~07이다 |
| 충돌 조건 확인 과정 | 요청 간격과 기한까지 남은 시간을 바꿔 가며 실제 비즈니스 상황에 가까운 조건을 만든다 |
| 정책 결정 과정 | 앞의 두 과정에서 확인한 실제 동작과 데이터로 정책을 정한다. 다른 서비스의 정책 사례 조사는 이보다 뒤에 둔다 |
| 구현 과정 | 정한 정책대로 코드를 고친다 |
| 정책 검증 과정 | 같은 테스트를 다시 실행해 정한 정책대로 처리되는지 확인한다 |

문제 확인 과정에 필요한 테스트 지원 기능(서버 시계 설정, 자동 처리 실행, 요청 일시 중지)은 운영 코드(`src/main`)에 넣고, 테스트 설정을 켰을 때만 동작하게 한다. 테스트하는 동안에만 이 설정을 켜고 DB 계정을 `TOYCHAT_TEST`로 바꿔 배포하며, 테스트가 끝나면 설정을 끄고 `TOYCHAT`으로 되돌려 다시 배포한다. 결과 확인 SQL은 로컬 노트북의 SQL Developer로 직접 실행한다.
