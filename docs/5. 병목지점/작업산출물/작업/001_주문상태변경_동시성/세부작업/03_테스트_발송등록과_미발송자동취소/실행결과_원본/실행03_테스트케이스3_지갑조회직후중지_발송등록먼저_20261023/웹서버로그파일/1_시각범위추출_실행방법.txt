1_시각범위추출.py 실행 방법

[하는 일]
서버 로그(chatservice.log)에서 지정한 시각 범위의 로그 기록만 뽑아 새 파일로 저장한다.
시각으로 시작하지 않는 줄(p6spy의 SQL 줄, 예외 스택 줄, 빈 줄)은 바로 앞 시각 줄에 딸린 줄로 함께 뽑는다.
원본 로그는 바꾸지 않는다. 출력 파일이 이미 있으면 덮어쓰지 않고 중단한다.

[실행 명령] PowerShell에서 아래 두 명령을 차례로 실행한다.

cd "E:\devSpace\SpringBootProjects\ChatService\docs\5. 병목지점\작업산출물\작업\001_주문상태변경_동시성\세부작업\03_테스트_발송등록과_미발송자동취소\실행결과_원본\실행03_테스트케이스3_지갑조회직후중지_발송등록먼저_20261023\웹서버로그파일"

py -V:3.13 .\1_시각범위추출.py --input .\chatservice.log --output "E:\devSpace\SpringBootProjects\ChatService\docs\5. 병목지점\작업산출물\작업\001_주문상태변경_동시성\세부작업\03_테스트_발송등록과_미발송자동취소\실행결과_가공\실행03_테스트케이스3_지갑조회직후중지_발송등록먼저_20261023\실행03_서버로그_시각추출.log" --start 2026-10-23T14:31:50 --end 2026-10-23T14:36:00

[인자]
--input   원본 로그 파일
--output  뽑은 결과를 저장할 파일. 폴더가 없으면 만든다
--start   시작 시각. 이 시각의 기록은 포함한다. 로그와 같은 한국 시각으로 적는다
--end     끝 시각. 이 시각의 기록은 포함하지 않는다. 생략하면 파일 끝까지 뽑는다

[py -V:3.13]
이 노트북에 설치된 Python 3.13으로 실행하라는 뜻이다. python 명령은 Python 설치 관리자로 연결되어 있어 쓰지 않는다.

[실행03의 시각 범위]
실행03의 서버 로그는 14:31:55.422(주문 만들기의 처리 기준 시각 고정 요청의 처리 시작)부터 14:35:27.301(재개 제어 뒤 처리 기준 시각 고정 해제 요청의 처리 끝)까지 있다.
같은 로그 파일에는 07:15:40의 HTTP 요청 헤더를 해석하지 못한 오류 기록, 14:27:49의 서버 확인 요청(멈춘 요청 목록 조회와 처리 기준 시각 조회), 그 뒤의 로그인(14:31:43~14:31:44, 테스트케이스2·3의 회원 네 명)도 들어 있으므로, 로그인 기록이 빠지도록 범위를 14:31:50~14:36:00으로 잡는다.
재개제어_기록.txt(노트북 시각)와 서버 로그(서버 시각)는 시계가 달라 시각을 그대로 비교하지 않는다. 같은 재개 동작을 서버 로그는 재개제어_기록.txt보다 요청 A에서 1572.3 ms, 요청 B에서 1574.4 ms 큰 시각으로 기록했다(서버 시각 − 노트북 시각).

[결과 확인]
실행하면 화면에 원본 줄 수, 시각 범위, 뽑은 로그 기록 수와 줄 수, 첫 기록과 마지막 기록의 시각, 저장한 파일 경로가 나온다.
실행03 범위로 실행하면 원본 322줄에서 109건, 215줄이 나오고, 첫 기록 시각은 14:31:55.422, 마지막 기록 시각은 14:35:27.301이다.
