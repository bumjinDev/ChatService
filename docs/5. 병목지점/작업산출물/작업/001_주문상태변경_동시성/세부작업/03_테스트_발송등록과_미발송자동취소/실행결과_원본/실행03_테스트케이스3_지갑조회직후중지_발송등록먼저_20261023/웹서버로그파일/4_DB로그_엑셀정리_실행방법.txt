4_DB로그_엑셀정리.py 실행 방법

[하는 일]
3번 스크립트로 뽑은 p6spy 기록(서버가 DB에 보낸 SQL과 커밋의 기록)을 엑셀 파일 하나로 정리한다.
p6spy 기록에는 서버 스레드 이름만 있고 어느 요청의 기록인지는 없으므로, 1번 스크립트로 뽑은 서버 로그(시각추출 파일)를 함께 읽어
각 서버 스레드가 그 시각에 어느 요청을 처리하고 있었는지 알아낸다. 시각추출 파일의 내용은 엑셀에 넣지 않는다.
입력 파일은 읽기만 한다. 출력 파일이 이미 있으면 덮어쓰지 않고 중단한다.
이 스크립트는 세부 작업 02의 스크립트를 이 세부 작업의 요청 구성(요청 A는 판매자의 발송 등록, 요청 B는 테스트 지원 API로 실행한 미발송 자동 취소)에 맞게 고친 사본이다.
테스트 지원 API의 요청은 서버 로그에 「요청 처리 시작」 기록이 없으므로, 테스트 지원 요청 로그 필터가 남기는 「[테스트 지원 요청] 처리 시작」·「처리 끝」 기록으로 그 요청을 찾는다.
저장한 값 열에는 주문의 거래 상태·배송 상태·취소 정보·종료 시각, 발송 정보, 지갑의 잔액·갱신 시각, 잔액 변동 내역의 종류·금액·변동 후 잔액·기록 시각을 넣는다.

[시트 구성]
1_원본       p6spy 기록 하나를 한 행으로 두고, 서버 시각·서버 스레드·커넥션 번호·기록 종류·p6spy가 기록한 실행 시간·SQL로 나눈다.
2_요청별정리 기록을 요청(요청 A, 요청 B, A-2, 주문 만들기의 요청)별로 묶고, 요청 안에서는 트랜잭션별로 묶는다. SQL에서 SQL 종류·대상 테이블·WHERE 조건·저장한 값을 꺼내 열로 둔다.
3_시간값     요청 A와 요청 B의 데이터를 바꾼 트랜잭션을 한 표에 서버 시각순으로 둔다. 오른쪽에 계산값 표(각 트랜잭션의 첫 SQL부터 커밋까지의 시간, 두 트랜잭션이 동시에 진행된 구간)를 둔다.
각 시트 아래에는 열마다 무슨 데이터인지 적은 열 설명 표가 있다.

[실행 명령] PowerShell에서 아래 두 명령을 차례로 실행한다.

cd "E:\devSpace\SpringBootProjects\ChatService\docs\5. 병목지점\작업산출물\작업\001_주문상태변경_동시성\세부작업\03_테스트_발송등록과_미발송자동취소\실행결과_원본\실행03_테스트케이스3_지갑조회직후중지_발송등록먼저_20261023\웹서버로그파일"

[인자]
--p6spy   3번 스크립트로 뽑은 p6spy 기록 파일
--log     같은 실행에서 1번 스크립트로 뽑은 서버 로그 파일(시각추출 파일). 요청을 알아내는 데만 쓴다
--output  만들 엑셀 파일. 폴더가 없으면 만든다

[py -V:3.13]
이 노트북에 설치된 Python 3.13으로 실행하라는 뜻이다. 엑셀 파일을 만드는 openpyxl이 이 Python에 설치되어 있다.

[결과 확인]
실행하면 화면에 p6spy 기록 수와 기록 종류별 수, 요청별 서버 스레드와 기록 수, 요청 안의 트랜잭션별 커넥션 번호·트랜잭션 성격·기록 수·커밋 시각,
저장한 파일 경로가 나온다.
실행03으로 실행하면 53건(SQL 실행 45건, 커밋 8건)이 나온다. 요청 A는 커넥션 47(데이터를 바꾼 트랜잭션, 26.864 커밋)과 48(응답에 쓸 주문 조회),
요청 B는 커넥션 44(대상 주문 조회, 커밋 기록 없음)와 45(데이터를 바꾼 트랜잭션, 27.096 커밋)를 썼고, A-2는 커넥션 46에서 조회만 했다고 나온다.
주문 만들기의 세 요청(상품 등록, 충전, 결제)은 「그 밖의 요청」으로 나온다. 처리 기준 시각 고정·해제와 재개 제어의 요청은 SQL을 실행하지 않아 나오지 않는다.
3_시간값 시트의 계산값 표에는 요청 A의 첫 SQL부터 커밋까지 343 ms, 요청 B 647 ms, 두 트랜잭션이 동시에 진행된 구간 343 ms가 나온다.
