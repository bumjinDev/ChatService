## 2. 계획

[작업명세 03](../../작업명세/03_테스트계획_발송등록과_구매자취소.md)에 따라 다음 순서로 진행한다.

1. 테스트케이스를 정한다.
2. 발송 등록과 구매자 취소를 주문 조회 직후에 멈출 수 있도록 테스트 지원 코드를 바꾼다.

5. 결과를 작업명세 03의 「4.3 예상 결과(가설)」와 비교해 분석한다.

### 2026-10-19 테스트케이스와 테스트 지원 코드 변경

- 두 요청을 모두 주문 조회 직후에 멈출 수 있도록 테스트 지원 코드를 고쳤다. 두 위치는 같은 중지 위치 이름 `ORDER_READ`를 쓰고, 어느 요청인지는 요청 이름(A, B)으로 구분한다.
  - `src/main/java/com/chatservice/marketplace/order/service/ShipmentService.java`: 발송 등록이 주문을 조회한 직후, 판매자인지와 거래가 끝났는지를 검사하기 전에 멈추도록 했다.
  - `src/main/java/com/chatservice/marketplace/order/service/OrderCancellationService.java`: 2026-10-16에 주석 처리했던 당사자 취소의 주문 조회 직후 일시 중지 호출을 다시 켰다.
  - `src/main/java/com/chatservice/marketplace/testsupport/PausePoint.java`, `TestPause.java`: `ORDER_READ`의 설명과 일시 중지 코드의 주석이 발송 등록까지 가리키도록 고쳤다.
- 발송 등록과 당사자 취소가 현재 시각을 구하는 위치는 바꾸지 않았다. 테스트가 운영 코드의 동작을 그대로 확인하도록 하기 위해서다. 그래서 발송 등록은 주문을 조회하기 전, 곧 멈추기 전에 구한 시각을 발송 시각으로 저장하고, 당사자 취소는 재개된 뒤에 구한 시각을 취소 시각으로 저장한다.

## 6. 시스템 명세

**요청**

- 요청 A: `POST /ChatService/api/orders/{주문 ID}/shipment`. 판매자 로그인 쿠키와 본문 `{"carrierName":"편의점 택배","trackingNumber":"3621-0984-4170","requestId":"{UUID}"}`

- 주문 ID를 얻는 조회: 판매자 `GET /ChatService/api/orders/sales`, 구매자 `GET /ChatService/api/orders/purchases`

**코드**
