## 1. 개요

### 1.1 문서 목적

기존 ChatService를 중고거래 서비스로 확장하는 개발과 검증의 기준을 정의한다. 업무상 허용 조건과 관찰 가능한 결과를 명시하며 내부 구현 방법은 확정하지 않는다. 기획서와 확정 대화가 충돌하면 확정 대화를 우선한다. 특히 환불 합의 실패 시 무기한 보류 정책은 CH-001로 대체한다.

### 1.2 구현 범위

판매자 무응답 자동 환불과 판매자 거절에 따른 정상 완료는 이번 확정 범위다. 원안의 “합의 실패 거래의 강제 종결 제외”를 이 두 처리에 적용하지 않는다.

### 1.3 전제와 제약

개인 개발 프로젝트이며 실제 자금 이동 없이 회원 테스트 잔액으로 처리한다. 회원 인증 여부를 판단할 수 있어야 하나 인증 방식이나 기존 ChatService의 미확인 구현을 전제하지 않는다. 모의 배송은 시스템 내부 업무 과정이며 별도 외부 서비스나 특정 클래스 구조를 요구하지 않는다. 카테고리에 관계없이 동일한 구매·배송·취소·환불 규칙을 적용한다.

### 1.4 이번 구현과 후속 검증의 구분

작업계획 「다음주_화요일부터_금요일_작업계획_2026-10-06_10-09.md」의 2-1을 따른다. 이번 구현은 순차 요청의 정상 흐름, 입력·권한·현재 상태 검사, 저장·조회와 기본 자동 처리까지다. 아래 규칙과 수용 기준에서 동시 요청, 동일 요청 식별에 의한 중복 방지, 처리 도중 실패 시 일부 반영 방지를 언급한 부분은 후속 검토 목표이며 이번 완료 기준이 아니다. 순차 요청에서 이미 종료한 주문을 상태 검사로 거절하거나 자동 처리 대상에서 제외하는 기본 동작은 이번에 구현한다.

특히 F-003-AC-01, F-005-AC-01, F-006-AC-02, F-010-AC-01·02·04는 후속 검증 항목이다. 충전·메시지·결제는 기본 구현에서 호출마다 새 요청으로 처리하므로 잔액·재고가 남아 있으면 재전송도 다시 반영될 수 있다. 그 밖의 반복 요청은 현재 상태를 다시 검사해 허용하거나 거절한다. 응답 유실 시 저장 결과를 조회하며 자동 재전송은 하지 않는다.

트랜잭션 경계·락·결제 정합성·중복 요청 식별·실패 복구의 구체적인 해결책과 비교 실험은 여기서 정하지 않는다. 기본 구현 이후 사용자가 실제 문제를 확인하고 대안 학습, 테스트, 선택, 개선과 재검증을 진행한다. 본문의 ‘함께 반영’은 업무상 연결된 결과를 뜻하며 장애 상황의 보장을 검증했다는 뜻이 아니다. 과거 기획과정 문서의 기술 대안과 실험 수치는 현재 구현 지시가 아니다.

## 2. 사용자와 공통 업무 규칙

### 2.1 사용자 및 외부 주체

| 주체 | 역할 | 허용되는 주요 동작 |

| 구매 희망자 | 특정 상품의 구매를 희망하는 회원 | 타인 판매 중 상품 채팅·제안·구매 |

### 2.2 용어 정의

| 용어 | 의미 |
| --- | --- |
| 최초 판매 수량·남은 수량 | 최초 수량은 등록한 전체 판매 수량이고, 남은 수량은 아직 결제로 차감하지 않은 수량이다. |
| 주문 수량·적용 단가·총 결제액 | 한 주문의 구매 개수, 개당 적용 가격, 둘을 곱한 확정 금액이다. |

| 구매 확정 | 결제 성공으로 구매자와 주문이 확정된 사건. 정상 수령 확인과 다르다. |

| 합의 가격 | 별도 가격 제안을 판매자가 수락한 해당 상품·구매자 전용 개당 가격 |

| 배송 완료 안내 시점 | 최초 모의 배송 완료 시점. 열람·재접속·중복 처리로 갱신하지 않는다. |
| 보류 | 유효 환불 요청 후 판매자 응답 또는 자동 환불을 기다리는 비최종 거래 상태 |

| 환불 완료 | 구매자에게 실제 결제 금액 전액 반환을 완료한 최종 결과 |
| 취소 완료 | 발송 전 취소와 실제 결제 금액 반환을 완료한 최종 결과 |

#### 1.2 입력과 결과

| 항목 | 출처 | 필수 여부 | 의미와 허용 조건 |

**성공 시 결과:** 상품 정보와 최초 판매 수량·남은 수량이 저장되고 판매 중 상품으로 공개된다.

#### 1.3 기본 처리 흐름

등록 요청의 정보와 권한을 확인한 뒤 상품을 판매 중으로 등록한다.

#### 1.4 예외와 실패 결과

필수 정보 누락, 잘못된 카테고리·가격 또는 누락·0·음수·소수인 판매 수량이면 등록하지 않는다. 공통적으로 권한 없는 요청은 거절하며, 처리되지 않은 요청을 성공으로 안내하지 않는다.

#### 1.5 추가 규칙

상품 수정·삭제·판매 중단과 기존 등록 건의 수량 변경·재입고는 제공하지 않는다. 별도 등록은 과거 거래와 독립된 새 상품이다.
