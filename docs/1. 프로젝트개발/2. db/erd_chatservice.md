# ChatService DB 스키마 / ERD (TOYCHAT)

ChatService `src/main/java` 의 JPA 엔티티를 정적 분석해 도출한 Oracle 스키마 요약이다.
DDL 실행 파일은 `ddl_toychat.sql`.

## 도출 전제 (식별자 확정 근거)

- `application.yml` → `spring.jpa.hibernate.ddl-auto: none` : Hibernate가 스키마를 생성/검증하지 않음. 따라서 DDL 식별자는 Hibernate가 엔티티에서 도출하는 이름과 **정확히 일치**해야 한다.
- `physical_naming_strategy: PhysicalNamingStrategyStandardImpl` : 논리명 → 물리명 변환 없음(camelCase 유지, 언더스코어 미삽입). `@Column(name=...)` 이 있으면 그 값 우선.
- Hibernate는 식별자를 **따옴표 없이** SQL로 전송 → Oracle이 대문자로 처리. 그래서 물리 식별자는 아래 **대문자**가 실제 값이며, DDL에서 식별자에 큰따옴표를 쓰면 안 된다.
- 타입 매핑: `String`(length 미지정) → `VARCHAR2(255)`, `int` → `NUMBER(10)`, `java.sql.Date` → `DATE`.

## 테이블 목록

| 테이블 (Oracle) | 출처 엔티티 / 매핑 | 성격 |
|---|---|---|
| `USERENTITY` | `auth.exception.dto.AuthenticationEntity` `@Table("userentity")` | 인증(Spring Security)용 사용자 |
| `USERENTITY_ROLES` | `AuthenticationEntity.roles` `@ElementCollection` + `@CollectionTable("userentity_roles")` | 사용자 권한 목록(자식) |
| `MEMBERTBL` | `user.model.MembersEntity` `@Table("membertbl")` | 회원 마스터 |
| `CHAT_ROOM_CREATION_QUEUE` | `createroom.model.RoomQueueEntity` `@Table("chat_room_creation_queue")` | 방 생성 대기열 |

> 참고: `joinroom.dao.ChatRoom` 은 `@Entity` 가 아닌 순수 POJO(인메모리 상태 객체)라 테이블이 아니다. WebSocket 세션/방 상태(`ChatSessionRegistry`)와 대기열 추적(`InMemoryRoomQueueTracker`)도 JVM 인메모리 구조이며 DB 테이블이 아니다(→ `redis_keys.md` 참고).

## 1. USERENTITY

| 컬럼 (Oracle) | Java 필드 | 타입 | 제약 | 비고 |
|---|---|---|---|---|
| `USERID` | `userid` | `VARCHAR2(255)` | **PK**, NOT NULL | `@Id @Column(nullable=false)` |
| `USERNAME` | `username` | `VARCHAR2(255)` | NOT NULL | `@Column(nullable=false)` |
| `PASSWORD` | `password` | `VARCHAR2(255)` | NOT NULL | `@Column(nullable=false)` |

- PK: `PK_USERENTITY (USERID)`
- 파생 조회: `findByUserid`, `findByUsername` (단순 WHERE, 추가 컬럼 없음).

## 2. USERENTITY_ROLES  *(자식)*

| 컬럼 (Oracle) | 매핑 | 타입 | 제약 | 비고 |
|---|---|---|---|---|
| `USERID` | `@JoinColumn(name="userid", referencedColumnName="userid")` | `VARCHAR2(255)` | NOT NULL, **FK** | → `USERENTITY.USERID` |
| `ROLES` | `@Column(name="roles")` (원소) | `VARCHAR2(255)` | NULL | 권한 문자열 1건/행 |

- FK: `FK_USERENTITY_ROLES_USERID (USERID) → USERENTITY(USERID)`
- `List<String>` + `@OrderColumn` 없음 → **bag** 의미. PK/UNIQUE 없음(동일 USERID에 중복 권한 행 가능).
- 권장 인덱스 `IX_USERENTITY_ROLES_USERID(USERID)` — 엔티티 도출분은 아니나 FK 락 경합 완화용(DDL에 포함, 선택적).

## 3. MEMBERTBL

| 컬럼 (Oracle) | Java 필드 | 타입 | 제약 | 비고 |
|---|---|---|---|---|
| `ID` | `id` | `VARCHAR2(255)` | **PK**, NOT NULL | `@Id` (애플리케이션 지정 문자열) |
| `PW` | `pw` | `VARCHAR2(255)` | NULL | |
| `NICKNAME` | `nickName` | `VARCHAR2(255)` | NULL | StandardImpl → 변환 없이 `NICKNAME` |
| `TEL` | `tel` | `VARCHAR2(255)` | NULL | |
| `EMAIL` | `email` | `VARCHAR2(255)` | NULL | |
| `JOINDATE` | `joinDate` | `DATE` | NULL | `java.sql.Date` |

- PK: `PK_MEMBERTBL (ID)`
- 네이티브 쿼리 검증: `SELECT * FROM membertbl WHERE nickname = :nickname AND id != :id` — `membertbl/nickname/id` 를 따옴표 없이 참조하므로 위 대문자 식별자와 일치(불일치 시 ORA-00942/00904).
- 파생 조회: `findById`, `findByNickName`, JPQL `... WHERE m.id IN :userIds`.

## 4. CHAT_ROOM_CREATION_QUEUE

| 컬럼 (Oracle) | Java 필드 | 타입 | 제약 | 비고 |
|---|---|---|---|---|
| `ROOMNUMBER` | `roomNumber` | `NUMBER(10)` | **PK**, IDENTITY, NOT NULL | `@GeneratedValue(IDENTITY)` → `GENERATED BY DEFAULT AS IDENTITY` |
| `ROOMTITLE` | `roomTitle` | `VARCHAR2(255)` | NULL | |
| `CURRENTPEOPLE` | `currentPeople` | `NUMBER(10)` | NOT NULL | primitive `int` |
| `MAXPEOPLE` | `maxPeople` | `NUMBER(10)` | NOT NULL | primitive `int` |

- PK: `PK_CHAT_ROOM_CREATION_QUEUE (ROOMNUMBER)`
- `int` 3종은 NULL 불가(원시형) → NOT NULL 로 도출. INSERT 시 Hibernate가 IDENTITY 컬럼을 생략하면 DB가 채번.
- 사용 리포지토리: `RoomQueueJpa`(save), `RoomQueueEntityJpa`(`DELETE ... WHERE r.roomNumber = :roomNumber`).

## 관계(FK) 요약

```
USERENTITY (USERID) 1 ──< N USERENTITY_ROLES (USERID)      [FK_USERENTITY_ROLES_USERID]

MEMBERTBL                      (독립 — 선언된 FK 없음)
CHAT_ROOM_CREATION_QUEUE       (독립 — 선언된 FK 없음)
```

- 코드상 `MembersRepository.addMember()` 가 `MEMBERTBL` 과 `USERENTITY` 에 동시 저장(회원=인증 사용자 1:1 대응)하지만, **엔티티에 JPA 관계/외래키가 선언돼 있지 않으므로** 두 테이블 사이에 FK는 만들지 않는다(소스에서 도출되는 것만 DDL에 포함).
- 유일하게 선언된 FK는 `@ElementCollection` 이 만드는 `USERENTITY_ROLES → USERENTITY` 하나뿐이다.

## 실행/롤백 순서

- 생성(부모→자식): `USERENTITY` → `USERENTITY_ROLES` → `MEMBERTBL` → `CHAT_ROOM_CREATION_QUEUE`
- 삭제(자식→부모): `USERENTITY_ROLES` → `USERENTITY` → `MEMBERTBL` → `CHAT_ROOM_CREATION_QUEUE`
